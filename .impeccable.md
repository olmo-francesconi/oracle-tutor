# Oracle Tutor — Impeccable Design Context

## Design Context

### Users
Competitive and casual Magic players in equal measure — deck-builders, brewers, and Commander fanatics who need to find the right card fast. They arrive mid-session with a card concept in mind and need the tool to get out of their way. Power users who want raw filter control sit alongside casual players who search by feel ("something that protects creatures"). Both audiences expect speed above all.

### Brand Personality
**Minimal · Fast · Brutalist**

Oracle Tutor is a precision tool, not a destination. The aesthetic is Bauhaus-rooted: structure over decoration, function drives form, every element earns its place. No rounded corners, no gradients, no shadows. The warm newsprint background (#F0EDE6) gives it material weight without heaviness. The red accent (#CC1100) is used sparingly — a Bauhaus stripe, not a highlight system.

### Aesthetic Direction
- **Visual tone:** Brutalist editorial — think grid-strict newspaper layouts, ink-on-paper contrast, typographic hierarchy as the primary design element
- **Typography:** Big Shoulders Display (uppercase, 800–900 weight) for all headings and labels; DM Mono for all body/UI text. No system fonts, no Inter
- **Color discipline:** Strictly 5 tokens — `#F0EDE6` (bg), `#FFFFFF` (surface), `#111111` (ink), `#CC1100` (accent), `#7A7670` (muted), `#F5C400` (semantic divider). No new colors without strong justification
- **Borders:** 2px solid ink everywhere. Zero border-radius on UI chrome (card images use the physical card shape radius only)
- **Interaction:** Hard inversion on hover (`#111111` bg / `#F0EDE6` text) — no box-shadows, no blurs, no rings
- **References:** Bauhaus school posters, brutalist editorial design (early web zines, Swiss grid), Typewolf "mono" picks
- **Anti-references:** Glassmorphism, soft UI, rounded-pill buttons, gradient accents, any "SaaS dashboard" aesthetic

### Emotional Goal
**Flow & speed.** The search experience should feel frictionless — results appear without ceremony, filters apply instantly, nothing interrupts the hunt for the right card. Latency is a design failure. Empty states should prompt action, not apologize.

### Design Principles
1. **The grid is law.** Every element snaps to the 4px base unit. The top bar is always 56px. No exceptions without documenting why.
2. **Typography does the heavy lifting.** Hierarchy is expressed through font weight, size, and case — not color, depth, or decorative elements.
3. **Ink and newsprint.** UI chrome feels physical — like a printed card catalog. Surfaces are white or warm off-white; nothing floats.
4. **Speed is a feature.** Animations and transitions exist only to convey state changes, never to entertain. Keep them sub-150ms or skip them.
5. **Restraint over richness.** When in doubt, remove. One fewer element is almost always the right call.
